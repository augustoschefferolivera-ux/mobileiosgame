## Key question 1 — Music: which models/tools output stems, seamless loops and specific tempo/key; commercial rights per plan; legal status (Suno/Udio vs labels) as of Oct 2026

### Takeaway
As of October 2026 the "stems + tempo/key + commercial-clear" trifecta is best covered by (a) ElevenLabs' Eleven Music API (3 s–10 min, composition plans, official stem-separation endpoint, but **games excluded on self-serve tiers**), (b) Stability AI's Stable Audio 3 (open-weight Small/Medium, 44.1 kHz stereo, inpainting/continuation, BPM only via prompt text, Community License) and (c) the MIT-licensed ACE-Step 1.5 (explicit BPM/key/time-signature metadata control, built-in track separation, runs on <4 GB VRAM or a Mac). Suno is the quality leader for songs with vocals and now ships 12-stem splitting and a browser DAW, but its outputs sit under live UMG/Sony litigation (second suit filed 18 Sep 2026 against v6) and new monthly download caps; Udio has had downloads disabled since 29 Oct 2025 and is effectively unusable for shipping game assets.

### Inferences
- Capability matrix (derived from the findings above): **native stems** — Suno (12-stem Auto Split), Eleven Music (`separate_stems`), ACE-Step 1.5 (Track Separation), Mubert API (stems editing); **explicit tempo/key parameters** — ACE-Step 1.5 (metadata control), Lyria RealTime (bpm 60–200, scale enum; see Q4); **prompt-text-only tempo** — Stable Audio 3, Eleven Music, Suno; **no stems/tempo** — Lyria 3 sync models. **No tool surveyed advertises a native "seamless loop" export for music**; loop points must be created in post (see Q5), except ElevenLabs SFX v2 `loop` (Q2) and Mubert streaming loop mode.
- For a commercial mobile game, the safest licensing paths today are: self-hosted MIT/Apache models (ACE-Step 1.5, HeartMuLa, DiffRhythm, Stable Audio 3 Small/Medium if under Stability's revenue threshold), or Eleven Music **only on an Enterprise contract** (self-serve explicitly excludes "Studio Games" — a term ElevenLabs does not define in the cited summary; a small indie title may or may not be a "Studio Game", so written clarification is needed).
- Suno's output is high quality but carries two shipping risks for a game: (1) active UMG/Sony litigation and the "model laundering" theory could affect v6-generated assets; (2) the Sep 2026 download caps (20–60/month) make bulk soundtrack iteration expensive unless using Studio export. Udio should be excluded entirely until downloads return.
- Because every major vendor now watermarks (SynthID for Lyria, C2PA option for Eleven Music, Perth for Chatterbox), AI-origin disclosure in store listings may become auditable; this is a policy inference, not a documented requirement.

## Key question 2 — Sound effects: tools, quality for footsteps/UI/impacts, batch workflows, video-to-SFX

### Takeaway
ElevenLabs Sound Effects v2 (Sep 2025) is the only mainstream text-to-SFX API with a native seamless-loop flag (0.5–30 s, 48 kHz), making it the practical default for ambiences and UI/impact one-shots; Stable Audio 3 "Small SFX" (433M, CPU-capable, open weights, 120 s) is the leading self-hostable alternative. Video-to-audio research models (MMAudio, ThinkSound) are strong for synced Foley but their weights are non-commercial. No independent quality benchmark for footsteps/UI/impacts was found; practitioner guidance is to generate in batches, curate, then normalise per category.

### Inferences
- For a mobile game the practical SFX stack is: ElevenLabs SFX v2 via API/MCP for one-shots and loopable ambiences (set `prompt_influence` ≈0.5–0.7 for literal UI/impact prompts, lower for textured ambiences — inferred from the parameter's documented behaviour), plus Stable Audio 3 Small-SFX locally for unlimited variations without per-call cost. Both produce 44.1/48 kHz sources that must be downsampled/compressed for iOS (see Q7).
- Video-to-audio models are useful for cutscene Foley but should not be shipped from MMAudio/ThinkSound weights in a commercial title without a separate licence.
- Because no quality benchmark exists for footsteps/UI/impacts, the robust approach is to over-generate (e.g., 8–16 candidates per prompt) and curate by ear; the parameters above and the batch tooling make this cheap.

- Use of a real actor's likeness/voice (even non-union) should follow the SAG-AFTRA pattern (written consent + disclosure); open models that embed watermarks (Chatterbox/Perth) simplify provenance audits.

## Key question 4 — Runtime/adaptive audio: Lyria RealTime, generative engines in-game, procedural SFX, middleware (Unity/Unreal/FMOD/Wwise), iOS constraints, Reactional/Infinite Album

### Takeaway
True real-time generative music exists (Google's Lyria RealTime over a bidirectional WebSocket; Magenta RealTime 2 locally on Apple Silicon), but both are impractical for a shipped iOS game today: Lyria RealTime remains an experimental `v1alpha` API (no Vertex support, instrumental only, undocumented pricing) and MRT2 real-time needs a Mac. Mainstream middleware (Wwise, FMOD, MetaSounds) has no built-in generative-AI features; the realistic 2026 architecture is "generate offline → author adaptive layers/stems and loop points → play back with conventional adaptive logic", with rule-based engines like Reactional Music as a non-ML alternative.

### Cited Findings

**Lyria RealTime (Gemini API) — [GitHub primary unless noted]**
- Cookbook script: model `models/lyria-realtime-exp`; API version `v1alpha` ("Lyria RealTime is only experimental"); `client.aio.live.music.connect(model=...)`; output **48,000 Hz, 2 channels, 16-bit PCM** (`paInt16`), chunk 4200 frames, 1-second startup buffer to absorb jitter; prompts are `WeightedPrompt(text, weight)` lists sent with `set_weighted_prompts`; `bpm`, `scale` (enum e.g. `A_FLAT_MAJOR_F_MINOR`) and `top_k` set via `set_music_generation_config`, each followed by `reset_context()`; `play()/pause()/stop()`; filtered prompts are reported via `message.filtered_prompt`. — [google-gemini/cookbook Get_started_LyriaRealTime.py](https://github.com/google-gemini/cookbook/blob/main/quickstarts/Get_started_LyriaRealTime.py)

## Key question 5 — Workflows for best quality: prompt structures, mastering, loudness normalization, loop-point editing, batch generation + curation, LLM-agent orchestration

### Takeaway
A production-quality pipeline in 2026 is: (1) structured prompts or composition plans with explicit BPM/key where the API supports it; (2) over-generate in batches via SDK/MCP (ElevenLabs hosted MCP, Mubert skills, ACE-Step batch-of-8, Stable Audio CLI); (3) curate; (4) cut loops with automatic loop-point detection (PyMusicLooper) and spectral-matched endings; (5) separate or request stems for adaptive layers; (6) normalise per category to the ASWG-R001 mobile target (−18 LUFS, −1 dBTP) with ITU-R BS.1770 tools (pyloudnorm, ffmpeg-class tools), optionally mastering music beds with Ozone 12/LANDR.

### Cited Findings
- **Prompt controls that exist as parameters**: Lyria RealTime weighted prompts blend styles by weight (e.g., "minimal techno" 1.0 + "1980s synthwave" 0.3) with bpm/scale/density/brightness/guidance knobs; Eleven Music `composition_plan` with enforced section durations on v2/v2.5 and `force_instrumental`; ACE-Step 1.5 metadata control for duration/BPM/key/time signature; Stable Audio 3 only accepts BPM in prompt text ("124 BPM"); ElevenLabs SFX `prompt_influence` trades adherence for variability. — [effect-uai plans/music.md](https://github.com/betalyra/effect-uai/blob/main/plans/music.md); [elevenlabs-python music/client.py](https://github.com/elevenlabs/elevenlabs-python/blob/main/src/elevenlabs/music/client.py); [ace-step/ACE-Step-1.5](https://github.com/ace-step/ACE-Step-1.5); [Stability-AI/stable-audio-3](https://github.com/Stability-AI/stable-audio-3); [elevenlabs-python text_to_sound_effects](https://github.com/elevenlabs/elevenlabs-python/blob/main/src/elevenlabs/text_to_sound_effects/client.py)
- **Loop-point editing**: PyMusicLooper (MIT, 407 stars) automatically finds seamless loop points, offers interactive selection and brute-force mode, splits a track into intro/loop/outro files, exports loop points in samples, writes loop tags into copies, and extends tracks to a target length; formats MP3/OGG/FLAC/WAV (+ffmpeg for M4A/AAC/ALAC). — [arkrow/PyMusicLooper](https://github.com/arkrow/PyMusicLooper) **[GitHub primary]**
- An online looper tool offers loop in/out points, zero-crossing snap, BPM-grid alignment, crossfade and WAV export; Roblox mastering guidance: end a looping file with "the same spectral and dynamic character as its beginning", and normalise one-shots, loops, ambience and dialogue as **separate batches** rather than per-file. — [Tools4Music](https://tools4music.com/tools); [Mastering.to Roblox guide](https://mastering.to/roblox) **[secondary]**
- **Loudness targets**: LUFSNormalizer (PolyForm Noncommercial 1.0.0 — not usable in a commercial pipeline without a licence) encodes ASWG-R001 presets: Game (Console) −24 LUFS / −1 dBTP; **Game (Mobile) −18 LUFS / −1 dBTP**; Streaming −14 LUFS / −1 dBTP; it also supports batch and watch-folder modes. - pyloudnorm (MIT) implements ITU-R BS.1770-4 integrated loudness, loudness normalisation to a target LUFS, peak normalisation and EBU Tech 3342 loudness range — a permissive building block for batch normalisation scripts. — [csteinmetz1/pyloudnorm](https://github.com/csteinmetz1/pyloudnorm) **[GitHub primary]**
- **Stems for adaptive layers**: see Q1 (Suno Auto Split, Eleven `separate_stems`, ACE-Step Track Separation, Demucs/MSST).
- **Mastering**: iZotope Ozone 12 has an AI "Master Assistant" that analyses a track against professional references and proposes a chain; 20+ modules, stem EQ; tiers Elements $99 / Standard $199 / Advanced $499; LANDR offers instant cloud mastering from $12.99/month (Essentials) or $9.99 per track; LANDR = one-click, Ozone = full control. — [Dynamoi AI mastering tools (PT)](https://dynamoi.com/pt/learn/ai-music-distribution/ai-music-mastering-tools); [Futureproof Music School](https://futureproofmusicschool.com/blog/best-ai-tools-for-mixing-and-mastering) **[secondary]**

### Inferences
- A concrete loop recipe derived from the cited tools: generate music at a fixed BPM (ACE-Step metadata or "120 BPM" in a Stable Audio/Eleven prompt) → run PyMusicLooper to find the best loop region → trim to a whole number of bars → add a 5–20 ms crossfade at the seam → export intro/loop/outro → normalise the music batch to −18 LUFS/−1 dBTP → encode for iOS (Q7). ElevenLabs SFX v2 `loop=true` can skip the loop-finding step for ambiences.
- Because PolyForm-NC licensing excludes LUFSNormalizer from commercial use, a studio pipeline should script pyloudnorm (MIT) or an equivalent BS.1770 implementation.
- Agent orchestration is now first-class: Claude Code (or any MCP client) can call ElevenLabs/Mubert MCP tools directly, so a "prompt list → batch generate → auto-tag with ACE-Step BPM/key extraction → loudness normalise → export" pipeline can be fully scripted; human curation remains the quality gate given the absence of objective SFX metrics.

## Key question 7 (cross-cutting) — Mobile iOS integration: file sizes, formats, middleware, on-device models

### Takeaway
Treat AI generators as 44.1/48 kHz WAV sources and transcode for iOS: AAC (.m4a/.caf) for music streams (hardware decode, but not for many simultaneous voices), IMA4 or 16-bit PCM in CAF for short SFX, loop points authored externally; budget roughly 80–400 MB if shipping on-device TTS models (Kokoro CoreML ≈80 MB int8 vs ≈350 MB via swift-tts download; Supertonic ≈382 MB) and prefer pre-baked dialogue for a small download. Wwise/FMOD remain the adaptive-playback layer; no middleware offers runtime generation.

### Cited Findings

### Inferences
- Size budgeting example (derived): a 10-minute adaptive soundtrack with 3 stems per track at AAC 128 kbps ≈ 10 × 3 × 0.96 MB ≈ 29 MB; the same as 16-bit 44.1 kHz stereo PCM ≈ 318 MB — so music must ship as AAC while short SFX can stay PCM/IMA4 for polyphony. Downsampling SFX to 32–44.1 kHz mono where spatialised further halves size.
- Shipping on-device neural TTS adds ≥80 MB (Kokoro int8) and requires iOS 17/18+, which is justified only for dynamic/user-generated text; fixed dialogue should be pre-rendered (cloud TTS) and compressed to AAC/Opus-equivalent.
