## KQ1. Which image models are best for game art right now, and which handle transparency, pixel art, vector/flat UI and multi-view consistency?

### Takeaway
As of mid/late 2026 the frontier for general game-art imagery is OpenAI's GPT Image 2 (top of the Artificial Analysis text-to-image arena, Elo ~1339), followed by GPT Image 1.5, HiDream-O1-Image-1.5 and Google's Nano Banana 2 (Gemini 3.1 Flash Image); for game work the practical differentiators are native transparent output (gpt-image-1.5 yes; GPT Image 2 only in a later preview flag), reference-image consistency (Nano Banana Pro accepts up to ~14 references), true SVG output (Recraft V4 Vector is the only mainstream option) and open weights with a permissive license (FLUX.2 [klein] 4B Apache 2.0; HiDream-O1 reportedly MIT).

### Inferences
- The snapshot id `gpt-image-2-2026-04-21` implies GPT Image 2 reached the API around 21 April 2026 (inference from the model id, no launch post captured).
- For an iOS game pipeline the pragmatic split is: gpt-image-1.5 or Nano Banana 2 for cheap iteration with native transparency; Nano Banana Pro for multi-reference character consistency and sheet layouts; Recraft V4 Vector for icons/UI as SVG; FLUX.2 [klein] 4B or SD 3.5 when self-hosting/LoRA training with a clean license matters.
- Arena Elo measures aesthetic/prompt-adherence preference on general prompts, not sprite usability (grid alignment, palette discipline, alpha edges); specialist tools can outperform frontier models for in-engine assets despite lower Elo.

## KQ2. Which game-specific platforms exist and what do they add over general models?

### Takeaway
Game-focused platforms add what raw models lack: pixel-grid-native generation, skeleton/rotation tooling (PixelLab), pay-per-asset pixel models plus an Aseprite extension (Retro Diffusion), custom style-model training on an art bible with sheet/rig templates (Scenario, Layer.ai), walk-cycle presets and sprite-sheet export (Ludo.ai), and free tilemap editing with engine export (Sprite Fusion); Krita AI Diffusion and ComfyUI give the self-hosted equivalents.

## KQ3. How do people generate animated sprites (walk/attack cycles) with AI?

### Takeaway
Four routes are in use: (1) frame-set generation by multimodal editors (Nano Banana Pro via the ComfyUI Sprite Sheet template or direct prompting), (2) pixel-native skeleton/pose animation (PixelLab, Retro Diffusion animations, Ludo walk presets), (3) image-to-video (Kling 3.0, Veo 3.1, Wan 2.6, Runway Gen-4.5) then frame extraction + background removal + alignment, and (4) AI-assisted cut-out rigging for Spine (open-source Claude skill, Layer/Scenario templates) — with Spine's developers stating auto-rig is not on their roadmap.

### Cited Findings
- Frame-set generation with Nano Banana Pro: Rosebud guide — request a full sheet or individual frames ("6 separate frames for a walk animation"); refine with "Align all frames on the same baseline", "Keep lighting consistent", "Match exact character proportions"; "Always export as PNG to keep transparency. For multi-frame sheets, verify the grid is clean and evenly spaced." — [Rosebud AI guide](https://rosebud.ai/blog/how-to-create-a-sprite-sheet-with-ai-using-google-gemini-and-nano-banana-easy-guide)
- ComfyUI Sprite Sheet Generator template: single sprite → idle/attack/walk/jump frames via GeminiImage2Node (Nano Banana Pro) + BatchImagesNode. — [comfy.org](https://comfy.org/workflows/templates-sprite_sheet-fe5600667e2c/)
- Pixel-native: PixelLab skeleton animation (see KQ2) — [PixelLab docs](https://www.pixellab.ai/docs/tools/skeleton-animation); Retro Diffusion animations $0.07–$0.25 each — [MCP listing](https://mcpservers.org/servers/retro-diffusion/retro-diffusion-mcp); Ludo.ai 30 walk presets, 4–64 frames, loop trimming — [Ludo docs](https://ludo.ai/docs/sprite-generator/walk-cycle)
- Frame-count practice: walk cycles 4–8 frames (4 for small sprites, 6–8 for 32×32+); make frame 1 a contact pose and the last frame the passing position before next contact to close the loop. — [sprite-ai.art frames](https://www.sprite-ai.art/blog/sprite-animation-frames); [sprite-ai.art animation guide](https://www.sprite-ai.art/guides/how-to-animate-pixel-art) (vendor)
- Hybrid manual workflow: generate base character → use as reference to draw key poses (contact, passing, up, down) → hand-draw in-betweens → assemble sheet → set per-frame timing in engine. — [sprite-ai.art](https://www.sprite-ai.art/guides/how-to-animate-pixel-art)
- Video-to-sprite workflow: upload a clip, "pulls clean frames out, removes the background, normalizes the alignment, and exports a single transparent PNG sheet"; alternative inputs are text prompt, drawn keyframes, reference video or motion preset. — [Seele.ai](https://www.seeles.ai/resources/blogs/how-to-animate-sprite-sheets-ai-game-development); [AISpriteSheet](https://www.aispritesheet.com/ai-sprite-sheet/ai-walk-cycle-generator); [SpriteFlow](https://spriteflow.io/)

## KQ4. Consistency techniques: LoRA, reference conditioning, style guides, palettes, post-processing

### Takeaway
Consistency comes from three layers used together: a trained style/character LoRA (FLUX.2 trainer on fal; FLUX.1-dev trainer on Replicate; FluxGym locally), reference-image conditioning at generation time (Nano Banana Pro up to ~14 refs; Retro Diffusion Pro up to 9; FLUX.2 multi-reference editing), and deterministic post-processing (BiRefNet/ToonOut background removal under MIT, pixel-grid re-quantization, upscaling).

### Cited Findings
- fal.ai FLUX.2 LoRA training: gather 20 to 1,000 images reflecting the same style/subject/identity; "dataset consistency will determine how well the LoRA performs"; trainer markets style consistency / brand-style use cases. — [fal blog: Training FLUX.2 LoRAs](https://blog.fal.ai/training-flux-2-loras); [fal-ai/flux-2-trainer](https://fal.ai/models/fal-ai/flux-2-trainer)
- Replicate `ostris/flux-dev-lora-trainer` (FLUX.1-dev): 1000–3000 steps, a trigger word, 12–18 high-resolution images; lowering LoRA strength to 0.8–0.95 helps stylized looks; poor datasets make the model less able to apply different art styles to the subject. — [Replicate README](https://replicate.com/ostris/flux-dev-lora-trainer/readme)
- FluxGym local LoRA training tutorials for character/style LoRAs. — [ThinkDiffusion](https://learn.thinkdiffusion.com/make-your-character-style-lora-stand-out-easy-lora-training-with-fluxgym/); [Lilys notes](https://lilys.ai/en/notes/training-lora-20260208/fluxgym-ai-influencer-lora-training)
- Reference conditioning: Nano Banana Pro up to ~14 reference images, up to 5 people consistent — [CometAPI](https://www.cometapi.com/pt/tag/gemini-3-pro-image/); Retro Diffusion Pro up to nine reference images — [Cinevva](https://app.cinevva.com/guides/ai-pixel-art-generators); Nano Banana Pro workflow: build a reference sheet first, then reuse it as reference in follow-up prompts — [SelfieLab](https://selfielabstudio.com/blog/nano-banana-pro-ultimate-character-sheets-tutorial-20260221) (blog; its "93%/95% consistency" numbers are unsourced and should not be relied on)
- Scenario's pitch is training custom models on an "art bible" for consistent output. — [AI Indigo](https://aiindigo.com/tools/alternatives/scenario)
- Background removal: BiRefNet is MIT-licensed (commercial use allowed); Replicate endpoint covers all 10 official variants + ToonOut; returns transparent cutout or raw matte; matte grow/shrink/blur, foreground color refinement, selectable inference resolution; animated GIF/WebP processed frame-by-frame. — [Replicate sprited/birefnet README](https://replicate.com/sprited/birefnet/readme)
- ToonOut: BiRefNet fine-tune for anime/stylized art; pixel accuracy 95.3% → 99.5% on anime test sets; pitched for extracting character sprites for 2D games/visual novels. — [Replicate birefnet-toonout](https://replicate.com/sprited/birefnet-toonout); [HackerNoon](https://hackernoon.com/birefnet-toonout-anime-background-removal-with-995percent-accuracy)
- ComfyUI BiRefNet nodes (RembgByBiRefNet) output RGBA + mask; official ComfyUI tutorial exists. — [RunComfy node doc](https://www.runcomfy.com/comfyui-nodes/ComfyUI_BiRefNet_ll/RembgByBiRefNet); [docs.comfy.org BiRefNet tutorial](https://docs.comfy.org/ja/tutorials/utility/remove-background-birefnet)
- Pixel-grid problem: generalist outputs come at uncontrolled sizes and need resampling to the target grid before engine use. — [Cinevva](https://app.cinevva.com/guides/ai-pixel-art-generators)
- UI-set consistency: pair every icon with a style-transfer workflow to hold one style across the set. — [Morphic](https://morphic.com/resources/images/game-ui-icon-images); ship a "style card (palette, corner radius, stroke weight, banned clutter)" with the prompts. — [Sorceress HUD pack guide](https://sorceress.games/blog/nest-an-ai-ui-generator-hud-panel-pack-2026)

### Inferences
- For a small iOS project: train one style LoRA on FLUX.2 [klein] 4B (Apache 2.0) or FLUX.1/2 [dev] via fal/Replicate (outputs usable commercially per invideo's reading; self-hosting [dev] needs BFL license), generate characters with a reference sheet, then run BiRefNet/ToonOut and a fixed palette quantization step.
- Native-transparent generation (gpt-image-1.5) avoids matte artifacts entirely and is preferable for UI/icons; BiRefNet is the fallback for models without alpha output (Midjourney, Nano Banana, FLUX).

- Pixelation/re-quantization tools (e.g., pixel-detector style downscalers) and current upscalers for sprites: search could not be run (budget exhausted).
- rembg's current default model and whether it bundles BiRefNet: not confirmed.
