## Key Question 1 — Runtime NPC/dialogue platforms (Inworld AI, Convai, NVIDIA ACE, Charisma.ai, Ubisoft, Sony, Microsoft, Unity Inference Engine/Sentis, Unreal NNE, Godot) and which shipped games use them (2025–2026)

### Takeaway
As of October 2026 the "AI NPC middleware" category has largely consolidated: Inworld AI pivoted away from its Character Engine toward voice/TTS and inference infrastructure, Convai still sells hosted characters (Unreal and web SDKs active; no iOS SDK visible), and NVIDIA ACE is the only stack with multiple commercially shipped integrations (inZOI, NARAKA: BLADEPOINT, PUBG Ally in testing) — but ACE's on-device path requires an RTX GPU, so it is irrelevant for iPhone. For a mobile iOS game, the realistic runtime options are (a) a game-engine inference runtime (Unity Inference Engine/Sentis, Unreal NNE, Godot GDExtensions around llama.cpp) running small models, (b) Apple's Foundation Models framework, or (c) a cloud LLM API behind your own backend.

### Inferences
- The two best-funded character platforms (Inworld, Convai) have both drifted toward enterprise voice/brand use; a mobile studio should not build a core loop on a third-party "character engine" SDK whose roadmap no longer centers on games. Treat them as replaceable voice/LLM back ends behind your own abstraction.
- Every commercially shipped on-device NPC (ACE) relies on a discrete RTX GPU and 0.5B–8B SLMs; there is no equivalent mobile SDK from NVIDIA. On iPhone the analogous route is Apple's Foundation Models framework (~3B, free) or llama.cpp/MLX with 0.6B–2B models (see Key Question 2).
- Unity Inference Engine/Sentis and Unreal NNE are production-grade for *small* ONNX models (vision, animation, audio) on mobile, but neither is documented as an LLM runtime for phones; LLM-on-device in those engines generally means bridging to llama.cpp/MLX native libraries or Apple's framework.

## Key Question 2 — On-device LLM/ML on iOS: Apple Foundation Models framework (iOS 26/27), Core ML, MLX, llama.cpp/ggml on Metal, ExecuTorch, MediaPipe/LiteRT-LM, ONNX Runtime; realistic sizes and latency on iPhone 15–17; App Store review guidance; Apple Intelligence integration

### Takeaway
Apple's Foundation Models framework is the most game-ready on-device path for iOS: a free, OS-resident ~3B 2-bit model with constrained-decoding structured output (`@Generable`), tool calling, and — in iOS 27 (shipping; App Store submissions opened 9 Sep 2026) — image input, an 8K-class context, a free 32K-context Private Cloud Compute model for small developers, and a provider protocol that lets Anthropic/Google cloud models slot into the same `LanguageModelSession` code. For custom models, MLX Swift and LiteRT-LM lead decode throughput on iPhone 17 Pro (~50–60 tok/s for 2B-class 4-bit models; ~160–190 tok/s for 0.6B), llama.cpp trails (~38–40 tok/s) but uses far less RAM; sustained throttling can cut 30–40%. App Review now explicitly requires disclosure and explicit consent before sending personal data to third-party AI (5.1.2(i), 13 Nov 2025).

### Cited Findings

**Apple Foundation Models framework — iOS 26 (WWDC25)**
- The framework exposes the on-device LLM behind Apple Intelligence via Swift on iOS, iPadOS, macOS and visionOS; all data stays on-device, works offline, and the model ships in the OS so it adds no app size. Apple's listed use cases include "on-the-fly in-game character dialog" — [WWDC25 Session 286 "Meet the Foundation Models framework"](https://developer.apple.com/videos/play/wwdc2025/286/)
- Model: "about 3 billion parameters, each quantized to 2 bits"; a "device-scale" model optimized for summarization, extraction, classification and content generation, "not designed for world knowledge or advanced reasoning" — [WWDC25 Session 286](https://developer.apple.com/videos/play/wwdc2025/286/)
- Guided generation: `@Generable`/`@Guide` produce structurally correct output via constrained decoding (strings, ints, doubles, bools, arrays, nested and recursive types); streaming returns `PartiallyGenerated` snapshots; properties generate in declaration order — [WWDC25 Session 286](https://developer.apple.com/videos/play/wwdc2025/286/)
- Tool calling via the `Tool` protocol (model decides when to call; arguments are `@Generable`, so tool names/args are never invalid; tools fixed at session init); errors to handle: guardrail violation, unsupported language, context window exceeded; an Instruments template measures request latency — [WWDC25 Session 286](https://developer.apple.com/videos/play/wwdc2025/286/)
- Apple's own deep-dive example is literally an NPC generator (`@Generable struct NPC { name, level 1...10, attributes (sassy/tired/hungry), encounter }`) and a runtime-defined "riddle" `DynamicGenerationSchema`; tool calls within one request can run in parallel; `GenerationOptions(sampling: .greedy)` gives repeatable output only for the same prompt/session/model version (an OS update can change output); the context-overflow error is `LanguageModelSession.GenerationError.exceededContextWindowSize`, recommended handling is to start a new session carrying the instructions and last response — [WWDC25 Session 301 "Deep dive into the Foundation Models framework"](https://developer.apple.com/videos/play/wwdc2025/301/)
- Custom adapters can be trained with Apple's toolkit but "require retraining as Apple updates the model" — [WWDC25 Session 286](https://developer.apple.com/videos/play/wwdc2025/286/)
- Device requirements are described by Apple only as "Apple Intelligence-enabled devices in supported regions"; secondary sources list iPhone 15 Pro or later, iPad mini (A17 Pro), iPad/Mac with M1 or later — [WWDC25 Session 286](https://developer.apple.com/videos/play/wwdc2025/286/); [Stora integration guide, Apr 2026 (secondary)](https://stora.sh/blog/2026-04-21-apple-foundation-models-framework-ios-26-integration-guide); [InfoQ, Jul 2025](https://www.infoq.com/news/2025/07/apple-foundation-models-ios26)

**Apple Foundation Models framework — iOS 27 (WWDC26, 8 Jun 2026; OS 27 App Store submissions open 9 Sep 2026)**
- Apple Developer News: "Jun 8, 2026 (WWDC26)" SDKs with new AI frameworks; "Sep 9, 2026: App Store submissions open for OS 27," listing "Apple Intelligence, the Foundation Models framework" among usable technologies; `ImageCreator` (Image Playground) deprecated 11 Jun 2026 and non-functional on iOS 27 — [Apple Developer News](https://developer.apple.com/news/)
- The on-device model was "rebuilt from the ground up," "better at logic and tool calling"; `contextSize` and `tokenCount(for:)` APIs (introduced in iOS 26.4) — slide example prints **8192**; guardrail false positives reduced in iOS 26.4 and again in iOS 27 — [WWDC26 Session 241 "What's new in the Foundation Models framework"](https://developer.apple.com/videos/play/wwdc2026/241/)
- Image input: the on-device model accepts `UIImage`/`CGImage`/pixel buffers/file URLs in prompts, any size (larger images cost more tokens/latency) — [WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- `PrivateCloudComputeLanguageModel`: much larger model, **32,000-token** context, `reasoningLevel` option, no API keys; "developers with fewer than 2 million first-time downloads get PCC with no cloud API costs"; users get daily limits (higher for iCloud+); requires an entitlement — [WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- New `LanguageModel` protocol lets any local or server model back a session; Apple open-sourced `CoreAILanguageModel` and `MLXLanguageModel` (run Hugging Face MLX models locally); "Anthropic and Google publish Swift packages for their latest models" — add via SwiftPM, swap the model, rest of code unchanged; third-party models need your own auth/billing — [WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/); [WWDC26 Session 339 "Bring an LLM provider to the Foundation Models framework"](https://developer.apple.com/videos/play/wwdc2026/339/) (platform minimums `.iOS(.v27)`)
- `response.usage` exposes input/cached/output/reasoning token counts; system tools `BarcodeReaderTool`, `OCRTool`, Spotlight-index local RAG tool; `DynamicProfile` for agentic state machines (instructions/tools/model/reasoning level switch per state); new Evaluations framework; `fm` CLI on macOS 27; Python SDK (`apple_fm_sdk`); the core framework is going open source and runs on Linux — [WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- Secondary reports agree (Gemini via Firebase Apple SDK; PCC free for Small Business Program-sized devs) but conflict on open-source timing — [TechTimes, 9 Jun 2026](https://www.techtimes.com/articles/318039/20260609/wwdc-2026-developer-tools-foundation-models-now-swaps-ai-providers-without-code-changes.htm); [Blake Crosley on PCC](https://blakecrosley.com/blog/foundation-models-private-cloud-compute); [Dracode, Jun 2026](https://dracode.dev/blog/2026-06-15-08-foundation-models-ios27-free-ai/)

## Key Question 3 — Cloud LLM integration patterns for games: cost control, latency, caching, guardrails, content safety, offline fallback; Anthropic/OpenAI/Google API features (structured outputs, realtime voice, prompt caching)

### Takeaway
Cloud text generation for NPCs is now cheap enough to be a rounding error per session on the small tiers (Claude Haiku 5.5 at USD 0.10/0.50 per million input/output tokens; cache hits at 5–10% of input price; 50% Batch discount for offline pre-generation), while realtime *voice* remains the expensive, latency-sensitive piece (OpenAI gpt-realtime audio at ~USD 32/64 per million audio tokens, ~300–500 ms time-to-first-audio per third-party comparisons). Structured outputs, strict tool schemas, prompt caching with stable prefixes, and mid-conversation system messages are the API features that map directly onto game needs (deterministic JSON for game state, cached world/character bibles, cache-safe dynamic rules).

### Cited Findings

**Anthropic (official pricing page read 10 Oct 2026)**
- Claude Opus 5.5: USD 4 input / 20 output per MTok; 5-min cache write 5, 1-h cache write 8, cache hit 0.20. Claude Sonnet 5.5: 2 / 10; cache hit 0.10. Claude Haiku 5.5 (prompts ≤100K tokens): 0.10 / 0.50; cache write 0.125 (5m) / 0.20 (1h); cache hit 0.01. Claude Haiku 4.5: 1 / 5. Claude Fable 5.1: 10 / 50, cache hit 0.25 — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Batch API: 50% discount on input and output (e.g., Haiku 5.5 batch 0.05 / 0.25) — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Prompt caching economics: 5-minute cache write 1.25× base input, 1-hour write 2×, cache read 0.1× (0.05× on Opus 5.5 / Sonnet 5.5; 0.025× on Fable 5.1); caching pays off after one read (5-min) or two reads (1-h); a read refreshes the TTL at no extra cost; minimum cacheable prefix is 512 tokens on the 5.5-generation models (4096 on Opus 4.6/4.5/Haiku 4.5) — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing); [Anthropic prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Cache is a byte-exact prefix match over `tools → system → messages`; timestamps or per-request IDs in the system prompt silently invalidate it; verify via `usage.cache_read_input_tokens`; mid-conversation `{"role":"system"}` messages let you inject operator instructions without invalidating the cached prefix (Opus 5/5.5, Sonnet 5.5, Fable 5/5.1, Haiku 5.5) — [Anthropic prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Structured outputs via `output_config.format` (the older `output_format` is deprecated) and `strict: true` tool schemas guarantee schema-valid JSON/tool inputs; 1M-token context on current models; server-side `fallbacks` handle `stop_reason: "refusal"` from safety classifiers — [Anthropic models overview](https://platform.claude.com/docs/en/about-claude/models/overview); [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Anthropic ships a Swift package for the Apple Foundation Models provider protocol (iOS 27), so Claude can be called from the same `LanguageModelSession` API as the on-device model — [WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/); [WWDC26 Session 339](https://developer.apple.com/videos/play/wwdc2026/339/)

**OpenAI Realtime API (third-party pricing pages; official page not reachable)**
- gpt-realtime-2.1 listed at USD 32 per million audio input tokens and 64 per million audio output tokens, cached audio input 0.40/M (0.30 on mini); ≈ USD 0.06/min input and 0.24/min output (third-party estimate) — [Layer3 Labs pricing guide (secondary)](https://www.layer3labs.io/guides/openai-realtime-api-pricing); [TokenMix (secondary)](https://tokenmix.ai/blog/openai-realtime-voice-api-2026-cost-latency)
- Realtime sessions cap at 60 minutes per connection with no documented resumption — [Zian AI comparison (secondary)](https://zian.ai/gemini-live-vs-openai-realtime-phone-agents/)

**Google Gemini Live API (conflicting third-party figures)**
- Gemini 3.1 Flash Live preview listed at USD 3/M audio input, 12/M audio output (≈ 0.005/min in, 0.018/min out) by one source; another cites 1.00 in / 20.00 out; a Sep 2026 comparison says context is re-billed every turn and caching is not supported on "Gemini 3.8 Live"; default session ~15 min, extendable via context compression — [Tech-Insider (secondary)](https://tech-insider.org/openai-vs-google-vs-qwen-voice-ai-apis-2026/); [Rogue Marketing pricing (secondary)](https://the-rogue-marketing.github.io/google-gemini-tts-speech-audio-api-pricing-may-2026/); [Webscraft (secondary)](https://webscraft.org/blog/gptrealtime2-vs-gemini-live-api-scho-obrati-dlya-golosovogo-agenta-u-2026-rotsi?lang=en)

**Platform-side guardrails and fallbacks**
- Apple's on-device model throws guardrail-violation and unsupported-language errors that the app must handle; instructions are prioritized over prompts "but by no means bulletproof" against prompt injection — [WWDC25 Session 286](https://developer.apple.com/videos/play/wwdc2025/286/)
- App Store 4.7.1 / 1.2 require filtering, reporting and blocking for chatbot-like content; 5.1.2(i) requires explicit consent before sharing personal data with third-party AI — [App Store Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
- Apple Private Cloud Compute is free for developers under 2M first-time downloads with daily per-user limits — an official zero-cost cloud fallback tier — [WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)

### Inferences
- Worked cost example (calculation, not a citation): an NPC exchange with ~1,000 cached-prefix tokens + 200 fresh input tokens + 150 output tokens on Claude Haiku 5.5 costs ≈ 1,000×0.01 + 200×0.10 + 150×0.50 per million ≈ USD 0.0001; 1,000 such exchanges ≈ USD 0.11. On Sonnet 5.5 the same ≈ USD 0.0018 per exchange. Text dialogue cost is therefore negligible versus voice: at the cited OpenAI rates a 10-minute spoken NPC conversation is on the order of USD 1–3.
- Pattern for a mobile game: generate deterministic game-affecting data (quest structs, item stats) with structured outputs/`@Generable`, keep the "world bible" in a cached prefix (≥512 tokens), use Batch API for offline pre-generation of dialogue pools, and reserve realtime voice for rare moments.
- Offline fallback is now first-class on iOS 27: the same session code can target `SystemLanguageModel` when the network is down or the player declined third-party consent. Design the content pipeline so every cloud feature has an on-device or pre-authored degradation.

### Gaps
- Official OpenAI and Google pricing pages could not be fetched; all Realtime/Live numbers are from vendor-adjacent blogs and conflict with each other.
- No game-studio case study with measured cloud NPC cost/latency in production was found.
- Anthropic realtime voice: no first-party voice API was found in the reachable docs; Anthropic's listed features are text/tool/structured output and prompt caching.

### Inferences
- Every playable neural engine found runs on datacenter or high-end desktop GPUs (H100-class, or ≥24 GB VRAM for open models). At Decart's published USD 0.02/second, a streamed world costs ~USD 72 per player-hour — two to three orders of magnitude above mobile F2P revenue per hour; frame-by-frame world models are not a viable mobile runtime in 2026.
- The commercially promising adjacent path for an iOS game is *asset-level* generation (World Labs Marble-style 3D export, Roblox-style text-to-mesh) consumed by a conventional engine — not neural rendering.
- Memory horizons (0.9 s in WHAMM; "minutes" in Genie 3/Muse) and the lack of authored game logic (health counters wrong, enemies fuzzy) are the stated blockers; "playing the model" is the honest description from Microsoft itself.

## Key Question 6 — Game-playing AI agents for QA/playtesting: computer-use agents (Anthropic, OpenAI Operator, Google Project Mariner / Gemini SIMA 2), modl.ai, agentic QA tools, Unity AI testing; reported results

### Takeaway
Agentic QA is real but narrow in 2026: screen-reading bots (modl.ai) and LLM agents (TITAN, deployed in MMORPG QA pipelines per its paper) catch mechanical failures — crashes, softlocks, missing assets, visual glitches — not experiential problems. Generalist game agents are improving fast (SIMA 2: 65% task completion vs 31% for SIMA 1 and ~71% for humans) but remain research previews, and 2026 benchmarks built from App Store/Steam games still report low scores for frontier VLMs, with "physical deadlocks" the main failure in a commercial 3D RPG. Anthropic's computer-use toolset is GA for desktop automation but documented for VMs/web, not real-time games.

### Cited Findings
- SIMA 2 (announced 13 Nov 2025): Gemini-powered agent that sees the screen and emits keyboard/mouse input; 65% task completion vs 31% for SIMA 1 (humans ~71%); self-improves via self-generated tasks and AI feedback; available to select academic researchers and game studios — [TechCrunch, 13 Nov 2025](https://techcrunch.com/2025/11/13/googles-sima-2-agent-uses-gemini-to-reason-and-act-in-virtual-world); [The Decoder](https://the-decoder.com/deepminds-latest-ai-agent-learns-by-exploring-unfamiliar-games-and-ai-built-worlds/); [Decrypt](https://decrypt.co/348569/google-deepmind-ai-agent-learns-adapts-plays-games-like-human); paper arXiv 2512.04797 (Dec 2025) — [awesome-game-gen list](https://github.com/imclab/awesome-game-gen)
- DeepMind (21 Aug 2026) argues a general gaming agent "could make QA more robust" by testing on every commit and adapting post-launch — a forward-looking position, with no named studio deployment — [DeepMind blog](https://deepmind.google/blog/from-atari-to-eve-online-building-on-15-years-of-ai-research-in-games/)
- modl.ai: agents "test your game externally, analyzing what's on screen and sending simulated inputs" with "no SDKs, no code hooks" (vendor); QA teams define tasks in plain language; runs from a dashboard or CI/CD; Unity and Unreal; custom pricing; one guide instead says it "requires integration work"; several note bots catch mechanical not experiential failures — [modl.ai](https://modl.ai/); [AI Central Resources review (secondary)](https://www.aicentralresources.com/tool/modlai); [Ampcome (secondary)](https://www.ampcome.com/post/best-agentic-ai-for-game-development)
- Anthropic computer use: `computer_toolset_20260801` (17 member tools incl. `screenshot`, `left_click`, `type`, `zoom`), GA on the Claude API and Google Cloud, supported on Claude Fable 5.1, Opus 5.5/5, Sonnet 5.5/5, Opus 4.8, Haiku 5.5; screenshots up to 2576 px long edge; recommended 1024×768–1366×768 displays; guidance to run in a least-privilege VM with human confirmation for consequential actions; no games/real-time guidance in the readable portion — [Anthropic computer use docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
- VideoGameBench (arXiv 2505.18134, May 2025): 7 public test games (Doom II, Pokémon Crystal, Zelda: Link's Awakening, Civilization I, The Need for Speed, Kirby's Dream Land, The Incredible Machine) + 3 secret; real-time async play, plus a "Lite" mode that pauses while the model thinks; models tested include Gemini 2.5 Pro, GPT-4o, Claude 3.7 Sonnet — [github.com/alexzhang13/VideoGameBench](https://github.com/alexzhang13/VideoGameBench)
- 2026 player-agent benchmarks: AI Gamestore (arXiv 2602.17594, Feb 2026) built from popular App Store and Steam games — "frontier VLMs score low"; PokeGym (arXiv 2604.08340, Apr 2026) pixels-only long-horizon in a commercial 3D RPG — "physical deadlocks are the main failure"; GameWorld (34 games, arXiv 2604.07429); GameVerse (video-reflection improvement, arXiv 2603.06656); OmniGameArena UE5 (arXiv 2606.09826, Jun 2026); StarBench real RPG client (arXiv 2510.18483); lmgame-Bench identifies vision brittleness and prompt sensitivity as key blockers (arXiv 2505.15146) — [awesome-game-gen list](https://github.com/imclab/awesome-game-gen)
- QA-specific research: TITAN — "LLM agents for automated MMORPG testing, deployed in real QA pipelines" (arXiv 2509.22170, Sep 2025); GBQA — agents as QA engineers hunting injected bugs (arXiv 2604.02648, Apr 2026); VideoGameQA-Bench — VLM glitch detection and bug-report generation (arXiv 2505.15952); SMART hybrid RL playtesting with code-coverage + LLM-intent rewards (arXiv 2512.12706); TempGlitch (arXiv 2605.21443) and visual bug detection (arXiv 2603.22706); game-dev agent benchmarks GameCraft-Bench (140 Godot 4 tasks, arXiv 2606.17861), GameDevBench (132 Godot tasks, arXiv 2602.11103), AutoUE with automated playtests (arXiv 2603.07106) — [awesome-game-gen list](https://github.com/imclab/awesome-game-gen)

### Inferences
- For an iOS studio, the deployable options today are vendor bots (modl.ai-style screen agents) or a self-built harness using a computer-use toolset against the iOS Simulator/device mirror; expect them to find crashes, softlocks, placeholder assets and performance drops, and to need task scripts. "Fun" and pacing evaluation remain human.
- Benchmarks show that mobile-style games (App Store titles) are still hard for frontier agents, so fully autonomous exploratory playtesting of a new iOS game is not yet reliable; scripted, goal-directed agent tests are.
