## KQ1 — Which general coding agents are used for game dev, and what do practitioners report (engines, shaders, physics, performance)?

### Takeaway
By October 2026 the general agents (Claude Code, OpenAI Codex, Cursor, Gemini CLI, GitHub Copilot, Windsurf, plus newer clients such as Google Antigravity, xAI Grok Build, Hermes Agent, OpenCode) are all wired into game engines mainly through **MCP servers and engine-vendor "plugins/skills"**, and the vendors themselves (Unity, Roblox) now ship official plugins targeting Claude Code and Codex first. Practitioner reports converge on: agents are strong on code-first stacks (C#, GDScript, TypeScript/Phaser, Rust), weak on binary/GUI-authored assets (Unreal .uasset, Unity scenes/prefabs) and on art; quality comes from giving the agent a way to run and *see* the game, not from bigger prompts.

### Inferences
- The "which agent" question has largely been answered by the engine vendors: Unity and Roblox target Claude Code and Codex (plus Grok for Unity), and Apple's Xcode 27 accepts Anthropic/Google/OpenAI agents via ACP + MCP. For an iOS-targeted game in 2026 the practical choice is therefore "Claude Code or Codex, inside Xcode 27 or driving Unity/Godot via MCP", with the other agents as secondary clients.
- Reported weaknesses map to *file format opacity*, not language: text-based assets (GDScript/.tscn, C#, Phaser JSON, Rust) are agent-friendly; binary assets (.uasset, .unity/.prefab YAML at scale, art) are not. This is why every serious bridge now adds screenshots, play-mode input injection and log reading.
- Independent, quantitative benchmarks of agents on game tasks do not exist in the sources found; quality claims are anecdotal or vendor demos.

### Gaps
- No studio case study, survey or benchmark comparing Claude Code vs Codex vs Cursor vs Gemini CLI on Unity/Godot/Unreal tasks was found.
- No game-specific reports for Devin, Jules, Windsurf or GitHub Copilot's coding agent.
- Vendor pricing pages (Anthropic plans, OpenAI Codex, Cursor) could not be fetched; figures are from third-party comparisons.
- HN/Reddit threads could not be opened (network restrictions); only search snippets/summaries were available.

## KQ2 — Which engine-native or official AI features exist now?

### Takeaway
Every major engine now has an official AI surface: Unity AI (Assistant + Generators, open beta for Unity 6 since May 2026) plus Unity's official agent plugin and Unity CLI (Aug–Sep 2026); Unreal Engine's in-editor AI Assistant (5.7, Nov 2025) and an experimental first-party MCP plugin (5.8, June 2026); Roblox's Assistant with agentic planning, Cube 3D/CubePart generation and a built-in Studio MCP server (2025–Oct 2026); Meta Horizon's Creator Assistant. Godot has no official AI feature and in June 2026 banned AI-agent/vibe-coded contributions to the engine itself, so Godot's AI story is entirely third-party MCP. Web engines (PlayCanvas, Phaser Editor) ship official MCP servers; Bevy/Defold rely on community bridges.

## KQ5 — Workflows that get AI to produce polished games: spec-driven dev, harnesses, automated playtesting, screenshot/video loops, TDD game loops, hooks/subagents, "agentic QA"

### Takeaway
The documented, reproducible recipe (Anthropic's own harness research, Nov 2025; Claude Code best-practices docs, 2026) is: an initializer that writes a JSON feature list and `init.sh`, one feature per session, git commits + a progress file, end-to-end verification through browser/GUI automation with screenshots, a Stop hook as a deterministic quality gate, and a fresh-context reviewer subagent. Game-specific harnesses (Claude-Code-Game-Studios, Godot AI, Unreal_mcp, Roblox plugin, PlayCanvas runtime tools) implement the same loop with engine play-mode, synthetic input, screenshot capture and log reading; the measured lesson from the 26k-star Game Studios template is that *more documents did not make a better game* — launching and looking at the game did.

### Cited Findings

**Anthropic's harness research (primary, 2025-11-26)**
- "Effective harnesses for long-running agents": failure modes were trying "to one-shot the app" and later sessions that "declare the job done". Solution: an **initializer agent** writes `init.sh`, `claude-progress.txt`, an initial git commit and "a comprehensive file of feature requirements… over 200 features… all initially marked as 'failing'" as **JSON** ("the model is less likely to inappropriately change or overwrite JSON files compared to Markdown"); **coding agents** work "on only one feature at a time", commit with descriptive messages, and verify end-to-end: "Claude mostly did well at verifying features end-to-end once explicitly prompted to use browser automation tools and do all testing as a human user would" (Puppeteer MCP screenshots); remaining limits: "Claude can't see browser-native alert modals through the Puppeteer MCP". Open question: single general agent vs specialised "testing agent, a quality assurance agent, or a code cleanup agent". — [anthropic.com/engineering/effective-harnesses-for-long-running-agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**Claude Code best practices and primitives (primary, 2026)**
- "Give Claude a way to verify its work… a test suite, a build exit code, a linter, a script that diffs output against a fixture, or a browser screenshot compared against a design." Three escalation levels: in-prompt ("take a screenshot of the result and compare it to the original. list differences and fix them"), **"As a deterministic gate: a Stop hook runs your check as a script and blocks the turn from ending until it passes"**, and "By a second opinion: a verification subagent". "Have Claude show evidence rather than asserting success: the test output… or a screenshot of the result." Also: plan mode; `/verify`; `/goal`; "Before treating a task as done, have a subagent review the diff in a fresh context"; bundled `/code-review` skill; `/batch` splits work "across 5 to 30 subagents… each in its own worktree"; `claude -p` for CI; "Hooks… are deterministic and guarantee the action happens" (vs advisory CLAUDE.md); warning that a reviewer "will usually report some [gaps], even when the work is sound". — [Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
- Hook events available (hooks doc, read 2026-10-10): PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, PermissionRequest, Elicitation, Notification, Stop, StopFailure, SubagentStart, SubagentStop, SessionStart, SessionEnd, PreCompact, TaskCompleted, TeammateIdle. **Game-specific harnesses and their measured lessons**
- Claude-Code-Game-Studios ran a controlled test: "Four games were built from one brief at different `modes.rigor` levels": `minimal` produced 1 doc (0 min overhead), `standard` produced 30 docs before the first line of game code (58 min). ### Inferences
- The consistent quality lever across Anthropic's research, the Game Studios measurement and every mature engine bridge is **observability of the running game** (play-mode launch + input + screenshots + logs + tests) combined with **deterministic gates** (Stop hooks, CI, differential tests). Documentation-heavy "spec-driven" rigor helps traceability but, per the only controlled measurement found, did not improve game quality.
- For mobile specifically, the equivalent loop is: Unity CLI/MobileBuildMCP builds → simulator launch → computer-use or MCP screenshot → compare against reference → fix; plus Unity's `2d-pixel-perfect`, `manage-sprite-atlas`, `optimize-*` skills for performance.
- Automated LLM playtesting is production-deployed in large studios (TITAN, modl.ai) but no turnkey indie product beyond engine-bridge screenshot/input tools was found.

### Gaps
- No published, end-to-end example that combines Stop hooks + feature-list JSON + engine play-mode screenshots for a *mobile* game.
- arXiv abstracts (2605.28258, 2609.16679) not readable; no benchmark numbers for LLM playtesting on 2D mobile games.
- No independent evaluation of modl.ai's accuracy or cost.
